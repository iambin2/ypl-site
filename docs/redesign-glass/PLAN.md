## 1. 디자인 법칙 (YPL Glass Laws)

1. **글래스는 층이다.** 글래스는 "콘텐츠 위에 떠 있다"는 의미일 때만 쓴다. 읽는 표면(표, 본문, 대진표 셀)은 반드시 불투명하다.
2. **빛은 하나다.** 화면마다 하나의 광원이 있고, 모든 글래스의 하이라이트, 그림자, 굴절이 그 광원을 따른다. 요소마다 빛 방향이 다르면 실패다.
3. **무대가 있어야 유리가 산다.** 글래스 뒤에는 항상 천천히 움직이는 네이비 빛의 장(場)이 있다. 빈 흰 배경 위의 글래스는 금지.
4. **색은 깊이를 위해 쓴다.** 기본은 무채색과 네이비. 블루는 상호작용과 현재 위치에만 쓴다. 의미 없는 색은 금지.
5. **모든 입력에는 응답이 있다.** 누르기, 호버, 포커스, 드래그, 스크롤 모두 100ms 안에 눈에 보이는 반응이 있어야 한다.
6. **요소는 순간이동하지 않는다.** 화면 전환과 상태 변화에서 같은 대상은 같은 요소로 이어져 움직인다 (shared element).
7. **움직임은 물리다.** 선형 이징 금지. 스프링 또는 정해진 곡선만 쓴다. 들어올 때는 감속, 나갈 때는 가속.
8. **숫자는 살아 있다.** 점수, 순위, 포인트는 바뀔 때 굴러가며 바뀐다. 고정폭 숫자(tabular)로 흔들림을 없앤다.
9. **폰이 본 무대다.** 390px에서 먼저 완성하고 데스크톱은 확장이다. 엄지 영역 안에 주요 조작을 둔다.
10. **아름다움은 성능 위에 있다.** 중급 폰에서 60fps를 못 지키는 효과는 빼거나 대체 경로를 쓴다.

## 2. 재질 시스템

| 층 | 용도 | 재질 |
|---|---|---|
| L0 Stage | 페이지 배경 | 네이비 메시 그라디언트, 아주 느린 드리프트(40s 이상 주기), 미세 노이즈 |
| L1 Surface | 표, 본문, 카드 본체 | 불투명. 다크: `navy-900` 계열 / 라이트: 오프화이트 |
| L2 Glass | 상단 바, 탭 바, 세그먼트, 플로팅 버튼 | blur 20–24px, saturate 160%, 틴트 8–12%, 내부 1px 하이라이트 테두리 |
| L3 Sheet | 바텀시트, 드롭다운, 팝오버 | blur 32–40px, 틴트 강하게, 큰 소프트 그림자 |
| L4 Overlay | 모달 뒤 배경 | 전체 블러 + 어둡게 |

**글래스 레시피 (모든 글래스 공통)**
- 상단 가장자리 하이라이트: 위→아래로 사라지는 1px 내부 그라디언트 (빛 방향 법칙)
- 바깥 그림자: 2단 (가까운 선명한 그림자 + 먼 퍼진 그림자)
- 노이즈 텍스처 2–3% (밴딩 방지, 재질감)
- **굴절(Liquid 가장자리)**: 점진적 향상. Chromium에서만 SVG `feDisplacementMap`으로 가장자리 굴절, 주요 1–2개 요소(탭 바, 대표 CTA)에만. Safari/Firefox는 일반 블러
- `prefers-reduced-transparency` 및 `@supports not (backdrop-filter)` → 불투명 대체

**예산:** 한 화면에 동시에 보이는 backdrop-filter 요소 최대 4개. 스크롤 중 블러 반경 변경 금지.

## 3. 색

- **Navy 스케일** (배경, 표면): `navy-950` ~ `navy-50`, 10단계. 기준은 깊은 미드나이트 네이비
- **Blue 스케일** (상호작용): 링크, 선택 상태, 포커스 링, 현재 탭, 진행 표시
- **Neutral**: 텍스트와 구분선. 순수 #000/#fff 대신 네이비 기운이 아주 약간 섞인 회색
- **Semantic**: 승/패, 성공/오류만. 채도를 낮춰 네이비 무대와 어울리게
- 테마: **다크(네이비) 우선**, 라이트(아이스 블루와 화이트)는 같은 토큰 이름으로 재정의. 둘 다 1급 지원
- 대비: 본문 4.5:1, 큰 숫자와 제목 3:1 이상. 글래스 위 텍스트는 최악의 배경을 기준으로 검증

## 4. 타이포

- 한글과 라틴 공통: Pretendard Variable (본문, UI)
- 디스플레이: 라틴 숫자와 제목용 기하학적 산세리프 1종 (후보: Inter Display, Geist, Unbounded 유지 여부는 결정 필요)
- 숫자: `font-variant-numeric: tabular-nums` 전역 적용 (표, 점수, 순위)
- 스케일: 폰 기준 6단계, `clamp()`로 데스크톱 확장. 제목 자간은 음수, 작은 라벨은 양수

## 5. 모션 시스템

**토큰**
- 지속시간: `instant 100ms` / `fast 180ms` / `base 260ms` / `slow 420ms` / `stage 700ms`
- 이징: `out` 감속 곡선, `in-out`, 스프링 2종(`spring-snappy`, `spring-soft`)은 CSS `linear()`로 정의
- 사용자가 직접 일으킨 동작은 `fast`, 시스템이 보여주는 변화는 `base`, 페이지 전환은 `slow`

**전환**
- 페이지(`?view=`) 전환: View Transitions API. 공통 요소(로고, 탭 바)는 고정, 콘텐츠만 교차. 목록 항목→상세는 shared element 이동
- 미지원 브라우저: 페이드 + 8px 이동으로 대체
- 스크롤 연출: `animation-timeline: view()`로 섹션 진입 시 블러 해제 + 상승. 한 번만, 과하지 않게
- `prefers-reduced-motion`: 이동과 스케일 제거, 투명도 변화만 남김

## 6. 마이크로 인터랙션 목록

| 대상 | 동작 |
|---|---|
| 버튼 | 누르는 순간 scale 0.97 + 하이라이트 어두워짐, 놓으면 스프링 복귀 |
| 글래스 표면 | 포인터 위치를 따라 가장자리 하이라이트가 이동 (데스크톱만, 폰은 기기 기울기 선택 사항) |

| 바텀시트 | 드래그로 닫기, 속도 기반 스냅, 뒤 배경이 살짝 축소 |

| 대진표 | 승자 확정 시 연결선이 다음 매치로 그려짐, 매치 탭 시 경로 하이라이트 |
| 로딩 | 스켈레톤 대신 글래스 위로 빛이 한 번 지나가는 shimmer |

| 포커스 | 블루 글로우 링, 키보드 사용 시에만 |
| 로고 | 로딩 화면에서 Wing Y에 빛이 한 번 스치는 등장, 이후 정지 |

## 9. 실행 단계

1. **법칙과 토큰 확정**: 이 문서를 확정하고 `tokens.css` (색, 재질, 모션, 타이포)와 새 규칙집 작성. 기존 규칙 문서 퇴역
2. **재질 프로토타입**: 단일 HTML에서 L0–L3 재질, 빛 방향, 굴절, 대체 경로를 실험. 아이폰 Safari와 안드로이드 Chrome에서 실측 (fps, 가독성)
3. **기본 컴포넌트**: 버튼, 세그먼트, 탭 바, 시트, 드롭다운, 모달, 토스트, 표, 카운터. 각각 상태(기본, 호버, 누름, 포커스, 비활성)와 모션 포함
4. **셸과 전환**: 헤더, 탭 바, 푸터, View Transitions 라우팅
5. **페이지 이식**: home → records → bracket → champions → builder → 나머지 → 관리자 순
6. **마감 패스**: 마이크로 인터랙션 전수 점검, reduced-motion, reduced-transparency, 라이트/다크, 390px와 1440px 캡처 비교
7. **문서화**: `DESIGN.md`, `CLAUDE.md`의 디자인 절, 컴포넌트 카드 갱신

각 단계 완료 조건: `npm test` 255개 통과, `npm run build` 성공, 콘솔 오류 0.
