# YPL Glass 결정 기록

`KICKOFF.md` 질문지에 대한 확정 답. 이 문서가 `PLAN.md`의 수치나 예시와 다르면 이 문서가 우선한다.
킥오프 시작 2026-10-11. 실험 페이지 1차 검토(같은 날)에서 바뀐 항목은 본문에 바로 반영했고, 바뀐 내용은 맨 아래 "1차 검토 반영"에 모았다.

## A. 정체성과 첫인상

- **A1** 유려함, 가벼움, 즐거움 (Family 앱). 조작하는 재미가 감탄의 원천.
- **A2** 셋 다. 우선순위는 누름 반응 → 페이지 전환 → 첫 진입 연출.
- **A3** 진지함 7 : 놀이 3. 기본은 진지한 리그, 승리와 우승 확정 순간에만 축하 연출.
- **A4** 레퍼런스 가중치: Family 30, Emil/Rauno 25, Apple 20, Apple Sports 15, Linear 10.
- **A5** 금지: 흔한 AI 랜딩 페이지(보라 글로우, 둥둥 뜬 블롭), 게임 런처 UI(과한 네온, 각진 HUD), 일반 대학 동아리 사이트. 셋 다.

## B. 테마와 색

- **B1** 다크 우선, 라이트 동등 지원. 둘 다 1급.
- **B2** (1차 검토로 변경) 무채색 베이스. 색조 없는 회색만 쓴다. 다크 무대 `#0A0A0A`, 표면 `#161616`. 라이트 무대 `#E7E7E7`, 표면 `#FFFFFF`.
- **B3** (1차 검토로 변경) 포인트 색 없음. 주 버튼은 테마의 반전색 채움(다크에서 흰색, 라이트에서 검정), 선택 표시는 흰 글래스 알약.
- **B4** (1차 검토로 변경) 1, 2, 3위는 무채색 명도 차이로 구분. 의미색도 쓰지 않고 굵기, 명도, 채움 반전으로 상태를 나타낸다.
- **B5** (1차 검토로 변경) 라이트 무대는 옅은 무채색 회색 위 흰 빛.
- **B6** 테마 전환은 아무것도 움직이지 않고 색만 바뀐다. (2026-10-12 변경) 원형으로 열리던 화면 복사본은 복사본과 실제 화면이 어긋나 입력창 같은 요소가 움찔했다. 색 토큰을 `@property` 로 등록해 `<html>` 에서 번지게 하고, 모든 요소가 그 자리에서 따라온다. 복사본은 없다.

## C. 글래스 재질

- **C1** 서리 유리. 뒤가 형태와 색만 보임.
- **C2** 굴절 없음 (PLAN.md의 feDisplacementMap 굴절 항목 폐기). (2차 검토로 변경) 가장자리는 위에서 가장 밝고, 가운데에서 사라졌다가, 아래에서 유리를 통과한 빛으로 다시 밝아진다. 몸체 위쪽에 광택(sheen)이 흐르고, 유리 뒤를 살짝 밝힌다(brightness).
- **C3** 광원은 바로 위, 천장 조명. 하이라이트는 위 가장자리에 좌우 대칭, 그림자는 바로 아래로 떨어짐.
- **C4** (1차 검토로 변경) 틴트 없음. 무채색 유리.
- **C5** 그림자 2단: 가까운 선명한 그림자 + 먼 퍼진 그림자. 광원(C3)에 맞춰 x 오프셋 0.
- **C6** (2차 검토로 변경) 보이는 노이즈 없음. 확대하면 자글자글해 보였다. 글래스에는 노이즈를 넣지 않고, 무대에는 띠 현상만 막는 1/255 수준의 디더만 남긴다.
- **C7** 글래스 허용 범위. 사용자 요청은 "최대한 많이, 자연스러운 선은 Claude가 판단".
  - 떠 있는 층은 전부 글래스: 상단 바, 하단 탭 바, 바텀시트, 모달, 드롭다운, 팝오버, 토스트.
  - 작은 요소: 보조 버튼, 칩과 세그먼트, 입력창. 주 버튼은 반전색 채움.
  - 읽는 표면은 불투명: 표, 본문, 대진표 셀, 대회 카드 본체.
  - 구현 원칙: 불투명 표면 위에 놓인 작은 요소는 `backdrop-filter` 없이 반투명 틴트 + 하이라이트로 같은 모습을 낸다 (뒤가 평평하면 블러는 보이지 않으므로). 실제 블러는 무대나 콘텐츠 위에 떠 있는 요소에만 쓰고, 한 화면 동시 4개 예산을 지킨다.
  - 경계가 자연스러운지는 재질 실험 페이지에서 직접 보며 조정한다.

## D. 무대(배경)

- **D1** 아주 느리게 흐르는 CSS 그라디언트 (40초 이상 주기).
- **D2** 무대가 반응하는 대상: 페이지 전환(빛의 배치가 천천히 이동), 대회 상태(접수 중, 진행 중, 종료에 따라 밝기나 온도), 스크롤(아주 약하게). 커서와 기기 기울기에는 반응하지 않음.
- **D3** 무대에 로고를 쓰지 않음. 로고는 내비게이션 등 제자리에만.
- **D4** 저사양, 배터리 절약 모드도 그대로. 별도 대체 경로 없음. (사용자의 움직임 줄이기 설정은 H4에서 따로 정함)

## E. 타이포

- **E1** 한글 본문 서체는 SUIT (Variable). `public/fonts/SUIT-Variable.woff2` (v2.0.5, OFL). 고정폭 숫자(`tnum`) 지원 확인함 (2026-10-11 실험 페이지에서 측정, `tnum` 적용 시 0–9 폭이 모두 같음).
- **E2** 디스플레이 서체 없음. SUIT 하나로 통일하고 굵기와 크기로 위계를 만든다.
- **E3** 제목은 크지만 여백이 주인공.
- **E4** 숫자는 SUIT 고정폭 숫자 (`font-variant-numeric: tabular-nums`). E1에서 지원을 확인해 대안은 필요 없음.
- **E5** 영문은 브랜드명(YPL)과 눈썹 라벨(Eyebrow)만. 메뉴와 본문은 한글.
- **E6** (3차 검토로 확정) YPL 워드마크는 서체가 아닌 그린 글자(SVG), 시안 B "띠". 굵은 글자를 12도 기울이고, Wing Y 꼬리를 가로지르는 띠와 같은 높이(56–64)로 세 글자를 한 줄의 틈이 관통한다. 파일 `public/brand/ypl-wordmark.svg` (currentColor). 상단 바에서는 Wing Y 28px 옆에 높이 14px, 간격 8px. 비교한 시안 보드: https://claude.ai/artifact/Eb249nYvjNPPtxkXT1kWqK

## F. 로고(Wing Y)

- **F1** (2차 검토로 변경) 단색 로고. 다크에서 흰색, 라이트에서 검정. 그림자와 재질 없음. 형태는 그대로, 반투명 채움 + 위 가장자리 하이라이트(C3 광원) + 2단 그림자로 유리처럼 렌더링. 로고 자체는 `backdrop-filter`가 아닌 SVG 재질로 표현한다. 작은 크기(내비게이션)에서는 채움 불투명도를 올려 가독성을 지킨다.
- **F2** (Claude 추천, 사용자 위임) 첫 방문에만: 흐린 상태에서 블러가 풀리며 또렷해지고, 로고와 같은 색의 빛 띠가 위에서 아래로 한 번 지나감. 이후 정지.
- **F3** 로고가 반응하는 순간은 로딩 중만 (로고가 흐려지고 같은 색의 빛 띠가 반복해 지나감).

## G. 레이아웃과 내비게이션

- **G1** 폰은 하단 글래스 탭 바 5칸.
- **G2** 탭 바: 홈, 공지, 대진표, 기록, 더보기. 더보기 시트에 칭호, 명예의 전당, 팀 빌더, 소개, 게시판. 팀 빌더는 대회 카드에서도 바로 진입.
- **G3** 데스크톱은 상단에 떠 있는 글래스 바 (화면 가장자리에서 떨어진 알약형).
- **G4** 스크롤 내리면 숨고 올리면 등장. 폰 탭 바와 데스크톱 바 공통.
- **G5** 콘텐츠 최대 폭 1200px.
- **G6** 모서리는 크고 둥글게 (iOS 문법). 반경 법칙: 안쪽 반경 = 바깥 반경 - 여백. 대표 카드 36, 카드 32(여백 20), 카드 안 타일 12, 컨트롤은 알약.
- **G7** 정보 밀도 중간.

## H. 모션 원칙

- **H1** 부드럽고 탄력 있는 iOS 스프링.
- **H2** 반동은 아주 살짝, 5% 이내.
- **H3** 빠르게. 사용자가 일으킨 반응은 대부분 200ms 이하, 페이지 전환 같은 큰 변화만 길게.
- **H4** 움직임 줄이기 설정 사용자에게는 이동과 확대를 빼고 투명도 변화만 남김.
- **H5** 순수 CSS + Web Animations API. 의존성 0. 스프링은 CSS `linear()`, 드래그를 놓을 때의 속도 이어받기는 직접 구현. (1차 검토로 변경) 페이지 전환은 View Transitions를 쓰지 않는다. 스냅샷 방식이라 끝날 때 글래스가 다시 그려지며 화면이 지지직거렸다. 살아 있는 화면 복사본이 사라지고 새 화면이 올라오는 방식으로 바꿨다. 테마 전환(B6)도 스냅샷이나 복사본 없이 색만 바뀐다.

## I. 페이지 전환

- **I1** 기본 전환은 페이드 + 살짝 위로.
- **I2** shared element 적용: 대회 카드 → 대진표 머리, 순위 행 → 선수 기록 제목, 공지 목록 제목 → 본문 제목, 탭 바 선택 알약(페이지가 바뀌어도 끊기지 않음).
- **I3** 뒤로 가기는 반대 방향 (앞으로는 위로, 뒤로는 아래로).
- **I4** (1차 검토로 변경) 전환이 브라우저 기능에 기대지 않으므로 모든 브라우저가 같은 전환을 본다. 뒤로 가면 떠났던 스크롤 위치로 돌아간다.

## J. 스크롤

- **J1** 섹션이 처음 보일 때 한 번, 블러가 풀리며 올라옴. 로고 등장(F2)과 같은 문법.
- **J2** 스크롤 물리는 브라우저 기본. 스크롤 라이브러리 없음.
- **J3** 상단 바 아래로 콘텐츠가 지나가면 블러 + 바 아래 가장자리에 옅은 그림자. 맨 위에서는 그림자 없음.
- **J4** 스크롤 끝 반응은 플랫폼 기본 (iOS 고무줄, 안드로이드 늘어남). 흉내 내지 않음.

## K. 마이크로 인터랙션

- **K1** 버튼 누름은 scale 0.97, 놓으면 스프링 복귀.
- **K2** 데스크톱 호버는 요소 안에서만 커서를 따라 은은한 하이라이트가 이동. 페이지 전체 광원은 바꾸지 않음 (C3 천장 광원 유지).
- **K3** 탭, 세그먼트 선택 표시는 액체 이동: 목적지 쪽으로 먼저 늘어났다가 뒤따라 줄어듦.
- **K4** 숫자는 자릿수마다 굴러가며 바뀜.
- **K5** 순위 변동은 행이 FLIP으로 새 자리로 미끄러지고, 오른 행은 잠깐 밝게 강조.
- **K6** 토스트는 아래(폰은 탭 바 바로 위)에서 스프링으로 등장, 여러 개면 뒤로 겹쳐 쌓임 (Sonner 방식).
- **K7** 포커스 링은 무채색 링(다크 흰색, 라이트 검정), `:focus-visible`일 때만.
- **K8** 텍스트 선택 색과 스크롤바는 테마에 맞춤. 커서 모양은 기본.
- **K9** 복사, 공유 성공은 버튼 아이콘이 체크로 바뀌었다가 돌아옴.
- **K10** 드래그: 바텀시트(끌어내려 닫기, 속도 기반 스냅), 대진표 이동.
- **K10-1** 팀 빌더 드래그 순서 바꾸기는 이번 개편에서 뺌. 현재 순서 변경 기능이 없고, 추가하면 제출되는 팀 순서가 달라지는 데이터 동작 변경이라서. 개편 후 별도 작업으로 검토.

## L. 상태 화면

- **L1** 로딩은 사이트 공용 로더 하나. (2026-10-12 변경) 글 없이 Wing Y 가 흐리게 자리를 잡고 빛 띠가 지나간다(F3 의 빛). 240ms 뒤에 나타나 짧은 로딩은 깜빡이지 않는다.
- **L2** 스플래시 없음. 로고 등장(F2)은 내비게이션의 로고에서 일어남.
- **L3** 빈 상태는 문장만.
- **L4** 오류는 차분한 문장 + 다시 시도 버튼.
- **L5** 축하(우승 확정, 제출 완료)는 흰 빛이 한 번 퍼짐. 색종이 없음.

## M. 컴포넌트

- **M1** 표는 행 구분 없음 + 넉넉한 행 높이.
- **M2** 표의 1–3위는 무채색 명도 차이로 강조 (B4). 표 머리 글자는 그 열의 정렬을 따른다 (순위 가운데, 이름 왼쪽, 출전 가운데, 포인트 오른쪽).
- **M3** 대진표는 선으로 연결된 트리. 승자 확정 시 연결선이 다음 매치로 그려짐.
- **M4** 대진표는 핀치 확대 축소 + 드래그 이동.
- **M5** 폰은 바텀시트, 데스크톱은 가운데 모달. 같은 내용이 화면 크기에 따라 모양만 바뀜.
- **M6** 드롭다운은 데스크톱 글래스 팝오버(트리거에서 커지며 등장), 폰은 바텀시트.
- **M7** 입력창은 채워진 글래스 필드 (C7에서 결정).
- **M8** 아이콘은 선형, 선택 상태만 채움 (iOS 탭 바 문법).
- **M9** 아이콘 세트는 Phosphor (Regular + Fill 짝). 패키지 설치 없이 쓰는 아이콘만 SVG로 복사.
- **M10** 칩과 배지는 알약 모양 글래스 (C7에서 결정).
- **M11** 버튼 위계: 주 버튼 반전색 채움, 보조 버튼 글래스, 3차 텍스트.

## N. 페이지별

- **N1** 홈 첫 화면은 상황에 따라: 진행 중 경기가 있으면 그것, 없으면 다음 대회.

- **N3** 개인 기록 상세는 시트 (폰 바텀시트, 데스크톱 모달). 누른 행이 시트 제목으로 이어짐 (I2). 라우팅 변경 없음.

### 간격 법칙

| 16 | 카드 안 블록 사이, 섹션 제목과 내용, 칸 안쪽 여백 |
| 20 | 카드 안쪽 여백 (대표 카드는 24) |

- **이름을 누를 때 이름이 크게 날아감** (I2 변경): 트레이너, 포켓몬, 역대 챔피언 시트는 누른 행을 날리지 않는다. 행은 제자리에 있고, 시트가 올라오기 시작한 90ms 뒤 시트 제목이 6px 아래에서 흐림이 풀리며 내려앉는다(460ms, J1과 같은 문법). 공지와 게시판 제목, 대진표 카드 제목은 화면 전환이라 그대로 이어진다.
- **토글의 액체 움직임이 보이지 않음** (K3 원인과 수정): 선택이 바뀐 직후 상단 바는 `document.fonts.ready`가, 세그먼트는 새로 만든 ResizeObserver의 첫 알림이 "애니메이션 없이 다시 맞추기"를 불러 움직임을 바로 끊고 있었다. 같은 자리로 다시 맞추는 호출은 진행 중인 움직임을 건드리지 않게 고쳤다. 렌즈는 둥근 양 끝 두 개와 몸통으로 다시 그려 transform만으로 움직인다(다음 화면을 그리는 동안에도 프레임이 끊기지 않음). 앞 가장자리가 먼저 튀어 나가고 뒤 가장자리가 한 박자 늦게 따라오며, 늘어나는 동안 최대 10% 가늘어졌다가 5% 이내의 반동으로 자리 잡는다.
- **유리 느낌이 덜하고 상단 바가 픽셀처럼 보임** (C2 보강): 원인은 균일한 1px 테두리(분수 배율 화면에서 그린 선처럼 보임)와 평평한 몸체. 테두리 빛을 위 가운데에서 가장 밝고 양 끝으로 사라지게 바꾸고, 안쪽 가장자리를 부드러운 빛과 그늘로 바꿔 두께를 만들고, 위 가운데의 반사광과 아래로 모이는 빛을 더했다. 그림자는 세 단. 바의 링크 트랙, 세그먼트 트랙, 입력창은 표면에 눌러 판 홈(groove)으로 바꿔 떠 있는 렌즈와 높낮이가 생기게 했다. 굴절(C2)은 여전히 쓰지 않는다. 상단 바는 맨 위에서도 작은 그림자로 떠 있고(J3 보강), 콘텐츠가 지나가면 그림자가 깊어진다.
- **전환 때 버벅임과 조회 최적화**: 렌즈가 합성 단계에서만 움직이게 됨(위). 기록과 대진표는 다시 들어오면 지난 조회 결과로 바로 그리고 새 조회는 뒤에서 받아 바뀐 경우에만 다시 그린다(관리자 모드는 늘 새 결과, 쓰기 뒤 다시 조회는 늘 새 결과로 덮음, `src/services/readCache.js`). 대진표 목록 조회는 대진표마다 4번 이어지던 왕복을 2번으로 줄였다(목록이 읽은 runtime 행을 다시 읽지 않고, 참가자 이름을 같은 왕복에서 받음). 실제 데이터로 이전 방식과 결과가 같음을 확인. 포켓몬 이름표는 방문마다 한 번만 만든다. 첫 화면 뒤 브라우저가 한가할 때 나머지 페이지 조각을 미리 받는다(실패해도 기록하지 않음). 데이터 미리 받기는 하지 않음(Supabase 전송량).
- **굴절 시험 페이지** (5차 검토에서 채택): 소스 `docs/redesign-glass/lab/refraction-lab.html`, 빌드 `node docs/redesign-glass/lab/build.mjs <outDir> refraction-lab`, 공유 링크 https://claude.ai/artifact/ToPgnJ9uk5mtDchwBoMtv7. 유리 조각마다 그 모양에 맞는 변위 지도를 그려 `backdrop-filter: url()`로 가장자리에서 뒤를 휘게 한다(Chromium만, Safari와 Firefox는 지금 유리). 굴절 세기는 가장자리 폭에 대한 비율로, 100%를 넘으면 가장자리에 뒤집힌 상이 생긴다. 2배 화면에서 흐려지거나 깨지지 않음을 확인.

## 6차: 심미성 컨설팅과 홈 재설계 (2026-10-12)

사용자가 "처음 사이트를 보는 사람의 눈으로, 심미성에만 무게를 두고, 제로부터 설계해도 좋다"고 맡김. 지금 홈 첫 화면이 정보의 나열이라 감탄이 없다는 지적. 유지할 것과 버릴 것을 가른 뒤 홈부터 다시 그렸다. 데이터 조회와 동작은 그대로다(새 조회 없음).

진단 (처음 보는 사람의 눈):
- 주인공이 없다. 첫 화면에 문구(왼쪽)와 챔피언 카드(오른쪽)가 같은 무게로 다투고, 폰에서는 문구와 설명이 첫 화면을 다 써서 처음 보이는 것이 사실이 아니라 주장이다.
- 대시보드 문법. 섹션 머리 + 목록 카드가 네 번 같은 무게, 같은 리듬으로 반복된다.
- 그릇이 너무 많다. 카드 안의 회색 받침(카드 속 카드)에 포켓몬이 갇혀 있어, 사이트에서 유일하게 살아 있는 색이 작고 답답하다.
- 큰 워터마크 숫자 "6"은 흔한 템플릿 장식이다.
- 데스크톱에서 공지 카드가 순위 카드 높이에 맞춰 늘어나 두 줄이 허공에 떠 있다.

유지: 무채색 흑연 무대, 굴절 유리 바, SUIT 하나, Wing Y와 그린 워드마크, 살아 있는 복사본 화면 전환, 액체 렌즈, 시트 물리, 원형 테마 전환. 이 재질과 모션은 이미 드문 수준이라 손대지 않는다.

새 홈 (Claude가 정함, 다시 정할 수 있음):
- **표지 하나와 세 장(章).** 표지의 세 문장 "모든 배틀. 모든 기록. 모든 챔피언."이 아래 세 장의 제목이 된다. 문구가 장식이 아니라 페이지의 뼈대가 된다. 모든 배틀은 최근 결과, 모든 기록은 시즌 순위, 모든 챔피언은 역대 챔피언.
- **표지는 한 장면만.** 가운데 정렬, 첫 화면을 채운다. 천장 빛이 떨어지는 바닥에 현재 챔피언의 우승 파티가 상자 없이 선다(포켓몬마다 접지 그림자). 폰은 앞뒤 두 줄(뒷줄은 작고 조금 어둡게), 넓은 화면은 가운데가 가장 가까운 한 줄. 그 아래 사진 설명처럼 "6대 챔피언 김현민 / YPL 시즌 2 우승 파티"(명예의 전당으로), 버튼 둘, 최신 공지 한 줄. 다가오는 대회가 있으면 파티 자리에 남은 날("D-6", 당일은 "오늘")이 서고, 파티는 셋째 장으로 내려간다 (N1 유지).
