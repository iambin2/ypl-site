# YPL Scoreboard 구현 지시서

이 문서는 `DESIGN.md`(규칙)와 이 폴더의 시안(그림)을 실제 사이트로 옮기는 작업 지시서입니다. 규칙은 `DESIGN.md`가, 생김새는 시안 PNG가 기준입니다. 둘이 다르면 멈추고 사용자에게 묻습니다.

## 2. 일하는 방법: 화면 하나씩, 시안과 나란히

한 번에 한 화면만 합니다. 각 화면마다:

1. **시안을 봅니다.** 아래 4장의 표에 적힌 PNG를 열어 보고, 같은 화면을 그린 `drafts-c*.html`의 마크업과 `c-core.css`, `c-kit.css`의 값을 읽습니다. 크기, 간격, 색은 거기서 가져옵니다. 눈대중으로 다시 정하지 않습니다.
2. **만듭니다.** 그 화면의 페이지 파일과 스타일을 시안의 구조대로 다시 씁니다. 옛 클래스에 색만 바꾸는 것은 "다시 만든 것"이 아닙니다. 데이터를 읽고 쓰는 코드(`src/services/`)는 바꾸지 않습니다.
3. **찍습니다.** 개발 서버를 띄우고 `compare.mjs`로 그 화면을 찍습니다.
   ```
   PLAYWRIGHT_DIR=C:/Users/jaebi/AppData/Local/npm-cache/_npx/9833c18b2d85bc59/node_modules/ node docs/redesign-next/compare.mjs http://localhost:5173/ypl-site/ <스크래치 폴더> home
   ```
   폰 390(어두운, 밝은)과 데스크톱 1440(어두운)을 화면 한 장과 전체 길이로 찍습니다.
4. **나란히 비교합니다.** 찍은 이미지와 시안 PNG를 함께 열어, 아래 7장의 확인 기준으로 하나씩 대조합니다. 다르면 고치고 다시 찍습니다. 데이터 때문에 달라진 것(이름, 숫자, 그림)은 차이가 아닙니다. 배치, 크기, 간격, 색, 상태가 다르면 차이입니다.
5. **끝냅니다.** 다 맞으면 그 화면의 스타일 파일을 `tests/designLaw.test.mjs`의 `REBUILT`에 넣고 `npm test`를 통과시킵니다. 사용자에게 시안과 결과를 나란히 보여 주고, 승인을 받은 뒤 그 화면만 커밋합니다.

시안에 없는 상태(빈 목록, 긴 이름, 데이터 없음 등)를 만나면 아래 5장의 규칙을 따르고, 거기에도 없으면 시안의 같은 부품으로 그려 보인 뒤 묻습니다.

## 5. 실제 데이터의 규칙

시안은 보기 좋게 지어 넣은 예시 값으로 그렸습니다. **시안의 이름과 숫자를 화면에 옮기지 않습니다.**

| 시안의 예시 값 | 실제로는 |
|---|---|
| 5일 남음, 37회 파이컵 NPC 배틀 7, 11.07 토 | 공지의 대회 정보(`eventAction`, `nextEvent`)에서 읽습니다. 2026-11-02 현재 다가오는 대회가 없어 `c23`의 상태가 맞습니다 |
| 현 챔피언 김현민 6대, 한카리아스 | 명예의 전당의 최신 챔피언(`loadChampions`)입니다. 지금은 정두호 5대, 그림은 명예의 전당의 그림입니다 |
| 대회 59, 트레이너 71, 시즌 3 | `loadFacts`의 대회 수와 트레이너 수입니다(지금 60과 55). 시즌은 랭킹 데이터의 시즌 수를 셉니다 |
| 대진표의 선수와 점수 | 대진 데이터입니다. 점수는 경기(게임)별 승자가 있으면 이긴 게임 수로, 없으면 승자만 표시합니다 |
| 신청 23 / 32, 파티 제출 18 | 신청 데이터입니다. 정원이 없는 대회는 `/ 32`를 쓰지 않습니다 |
| 공지, 게시글, 기록의 행 | 모두 실제 데이터입니다 |

비어 있거나 넘칠 때:

- **다음 대회 없음:** 카운트다운은 꺼진 칸 그대로, 램프는 꺼짐, 제목 자리에 "다음 대회 일정은 공지에 올라옵니다.", 주 행동은 "공지 보기" (`c23`).
- **대회 당일:** 라벨이 호박색 램프와 "오늘 대회 진행 중", 시작 시각을 84 시계로, 주 행동은 "대진표 보기" (`c9`). 홈이 이미 읽는 데이터만으로 지금 경기를 알 수 없으면 "지금 경기" 블록은 빼고 사용자에게 묻습니다.
- **100일 이상:** 칸이 셋이 됩니다. **긴 대회명:** 두 줄에서 말줄임표.
- **불러오는 중:** 모든 패널이 크기대로 서 있고 빛만 꺼진 판. 스피너와 로고 로딩 화면은 없습니다.
- **목록이 비었을 때:** `Empty`의 문장. 검색 결과가 없으면 꺼진 0 판과 두 문장 (`c9`).
- **그림:** 스프라이트마다 아래 여백이 다르고, 명예의 전당 그림은 잘린 원화일 수 있습니다. 모든 챔피언과 파티를 한 번씩 찍어 발이 바닥에 서는지 확인합니다.

## 6. 시안에 있지만 지금 없는 기능

아래는 시안에 그려졌지만 사이트에 아직 없는 기능입니다. **화면 작업에서 몰래 만들지 않습니다.** 이번 구현은 있는 기능의 생김새만 바꾸고 데이터 동작은 바꾸지 않습니다(`CLAUDE.md`). 만들려면 사용자에게 따로 묻습니다.

- 결과 입력 뒤의 "되돌리기" 토스트, 대진 배치의 끌어서 자리 바꾸기
- 공지 작성의 "지난 대회에서 불러오기", 대진표 만들기의 "지난 대회와 같게"
- 포켓몬 고르기의 "최근 고른 포켓몬"
- 테마의 "기기 설정"(지금은 어둡게와 밝게 둘뿐)
- 홈의 "지금 경기" 블록(위 5장)
- 파티 제출의 회차 목록: 데이터는 회차를 남기지만 화면이 읽고 있는지 확인하고, 새로 읽어야 하면 묻습니다

있는 기능인데 시안에 없는 것은 지우지 않고, 같은 부품으로 옮깁니다.

## 7. 확인 기준

한 화면이 끝났다고 말하려면 모두 맞아야 합니다.

1. **나란히 놓았을 때 같습니다:** 구획 순서, 패널의 크기와 이음매, 글자 크기와 굵기, 세그먼트와 램프, 반전된 것, 주 행동의 위치. 폰 390 어두운과 밝은, 데스크톱 1440.
2. **눈의 거리:** `DESIGN.md`의 The eye 표(바 아래 32, 구획 제목에서 내용 12, 구획 사이 52, 발끝과 바닥 0 등)를 찍은 이미지에서 잽니다. 1px 안.
3. **대비:** 모든 글자 4.5 이상, 램프 3 이상. 토큰 밖의 색이 없습니다.
4. **움직임:** 처음 열 때 꺼진 판에서 켜지고, 420 안에 끝나며, 돌아오면 다시 켜지지 않습니다. 줄이고 싶은 움직임 설정에서는 바로 섭니다.
5. **테스트:** `npm test` 통과, 그 화면의 스타일 파일이 `REBUILT`에 있습니다.
6. **데이터:** `src/services/`와 데이터를 쓰는 호출이 바뀌지 않았습니다.
