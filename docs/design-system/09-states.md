# 09 상호작용 상태

상태마다 규칙은 하나다. 버튼, 타일, 행, 입력창, 탭 모두 같은 규칙을 따른다.

| 상태 | 규칙 |
|---|---|
| 호버 | 면이 한 단계 올라간다(`bg` → `bg-2` → `bg-3`, `fill` 진하게). 화살표는 2px 밀리고 `ink`로. 150ms. 움직이거나 커지지 않는다. 마우스가 있는 기기에서만 |
| 누름 | 컨트롤 0.97배, 타일과 행 0.985배. 90ms에 눌리고 경쾌 스프링으로 돌아온다 |
| 포커스 | 키보드로 왔을 때만. `focus` 색 2px 링, 2px 띄워서, 요소의 곡률 그대로. 지우지 않는다 |
| 선택 | 여럿 중 하나: 세그먼트처럼 한 단계 위 면과 `shadow-thumb`. 하나뿐인 승자와 1위: `ink` 반전 |
| 현재 위치 | 내비게이션의 현재 페이지는 `fill` 캡슐 면, 글자 `ink` 600. 밑줄은 쓰지 않는다 |
| 비활성 | `opacity-disabled`(38%), 금지 커서, 호버와 누름에 반응하지 않는다. 가능하면 이유를 옆에 적는다 |
| 흐림 | 있지만 아직 정해지지 않은 것(미정 경기): `opacity-dim`(45%). 비활성과 다르다 |
| 로딩 | 300ms 안에 끝나면 아무것도 보이지 않는다. 넘으면 완성될 모양 그대로의 스켈레톤 |
| 오류 | `danger` 글자와 아이콘, 무엇이 잘못됐고 어떻게 고치는지 한 문장 |

## 세부

- 호버할 것처럼 보이는 것은 모두 호버에 반응한다. 같은 종류 중 하나만 반응하지 않는 일은 없다.
- 버튼이 처리 중이면 폭을 유지한 채 글자 자리에 16px 원형 진행 표시를 둔다. 두 번 눌리지 않는다.
- 입력창 포커스: 바탕이 `bg`로, 테두리가 `ink`로, 4px 바깥 후광(`fill`).
- 툴팁과 호버 미리보기는 이웃 요소를 가리지 않는다. 공간이 없으면 반대편으로 연다.
- 터치 기기에서는 호버 상태를 만들지 않는다(`@media (hover: hover)`).
